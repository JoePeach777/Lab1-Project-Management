## Теоретическое обоснование

### Композиция

**Композиция** — отношение между объектами, при котором один объект владеет другими объектами и управляет их временем жизни. Составные объекты не существуют независимо от своего владельца в рамках данной модели.

В C++ композицию можно реализовать с помощью полей-объектов, умных указателей и контейнеров, например `std::unique_ptr` и `std::vector`.

### Агрегация

**Агрегация** — отношение, при котором один объект содержит ссылки или указатели на другие объекты, но не владеет ими. Время жизни агрегируемых объектов не зависит от времени жизни агрегатора.

В данной работе менеджер проектов хранит невладеющие указатели на проекты.

### Статические члены класса

Статическое поле принадлежит классу в целом, а не отдельному экземпляру. Все объекты этого класса используют одну общую переменную.

Статические методы вызываются через имя класса и могут обращаться непосредственно к статическим членам класса.

В работе статические счётчики используются для подсчёта количества существующих объектов классов `Task` и `Project`.

### Паттерн Singleton

**Singleton (Одиночка)** — паттерн проектирования, который обеспечивает существование единственного экземпляра класса и предоставляет глобальную точку доступа к нему.

В данной работе `ProjectManager` реализован как Singleton с использованием статического локального объекта внутри метода `getInstance()`.

## Выполнение индивидуального задания — вариант 9

**Тема:** система управления проектами.

В индивидуальном задании реализована модель управления проектами, включающая три основных класса:

- `ProjectManager` — менеджер проектов, реализованный по паттерну Singleton;
- `Project` — проект, содержащий задачи и участвующий в отношении агрегации с менеджером;
- `Task` — задача, время жизни которой связано с содержащим её проектом.

### Модель классов

| Класс | Назначение |
|---|---|
| `Task` | Хранит название задачи и её состояние выполнения |
| `Project` | Хранит название проекта и список задач |
| `ProjectManager` | Управляет списком зарегистрированных проектов |

Каждая задача содержит название и признак выполнения. Проект содержит название и коллекцию задач. Менеджер предоставляет методы добавления, удаления и отображения проектов.

### Композиция

Композиция реализована между классами `Project` и `Task`.

Для хранения задач используется контейнер `std::vector<std::unique_ptr<Task>>`. Проект создаёт задачи и владеет ими. Когда проект уничтожается, принадлежащие ему задачи также уничтожаются.

Для демонстрации композиции создаётся временный проект с двумя задачами. После выхода из блока область видимости временного проекта заканчивается, проект и его задачи уничтожаются, а счётчик объектов `Task` возвращается к предыдущему значению.

### Агрегация

Агрегация реализована между классами `ProjectManager` и `Project`.

Менеджер хранит невладеющие указатели `Project*` на существующие проекты. Он может регистрировать проект, отображать список зарегистрированных проектов и удалять проект из списка регистрации.

При удалении проекта из менеджера сам объект `Project` не уничтожается. Его временем жизни управляет код, который создал этот объект.

### Статические члены

В классах `Task` и `Project` предусмотрены статические счётчики объектов.

- `Task::taskCount` хранит количество существующих объектов `Task`.
- `Project::projectCount` хранит количество существующих объектов `Project`.

Счётчики увеличиваются в конструкторах и уменьшаются в деструкторах. Статические методы `getCount()` позволяют получить текущее количество объектов.

Эта функциональность используется для проверки правильности создания и уничтожения объектов.

### Паттерн Singleton

Класс `ProjectManager` реализован по паттерну Singleton.

Метод `getInstance()` возвращает ссылку на единственный экземпляр менеджера. Конструктор класса закрыт, а копирование и присваивание запрещены.

В программе метод `getInstance()` вызывается дважды. Затем сравниваются адреса возвращённых ссылок. Совпадение адресов подтверждает, что оба вызова обращаются к одному экземпляру менеджера.

### Обработка ошибок

В программе предусмотрена проверка передачи нулевого указателя в метод добавления проекта.

Если вызывается `addProject(nullptr)`, выводится сообщение об ошибке, а некорректный указатель не добавляется в список.

Также проверяется повторное добавление одного и того же проекта и удаление проекта, который не зарегистрирован в менеджере.



## Ответы на контрольные вопросы

### 1. Что такое композиция?

Композиция — отношение между объектами, при котором один объект владеет другими объектами и управляет их временем жизни. При уничтожении владельца принадлежащие ему объекты также уничтожаются.

### 2. Чем агрегация отличается от композиции?

При композиции владелец управляет временем жизни составных объектов. При агрегации объекты существуют независимо, а агрегатор хранит ссылки или указатели на них без владения.

### 3. Как реализовать композицию в C++?

Композицию можно реализовать с помощью полей-объектов или умных указателей, например `std::unique_ptr`. В данной работе задачи хранятся в `std::vector<std::unique_ptr<Task>>`.

### 4. Как реализовать агрегацию в C++?

Агрегацию можно реализовать с помощью ссылок или невладеющих указателей. В данной работе менеджер хранит указатели `Project*` на проекты, созданные и управляемые вне менеджера.

### 5. Как отличаются времена жизни объектов при композиции и агрегации?

При композиции время жизни составного объекта связано с владельцем. При агрегации агрегируемый объект может существовать независимо от агрегатора.

### 6. Что такое статическое поле класса?

Статическое поле — переменная, общая для всех экземпляров класса. Оно существует независимо от количества созданных объектов этого класса.

### 7. Как объявить и определить статическое поле?

Внутри класса поле объявляется с ключевым словом `static`. В классическом варианте C++ его определение размещается вне класса:

```cpp
class Task {
public:
    static int taskCount;
};

int Task::taskCount = 0;
```

### 8. Что такое статический метод?

Статический метод принадлежит классу, а не конкретному объекту. Он может вызываться без создания экземпляра класса и не имеет указателя `this`.

### 9. Как использовать статические поля для подсчёта объектов?

Счётчик увеличивается в конструкторе и уменьшается в деструкторе. В данной работе такой механизм реализован для классов `Task` и `Project`.

### 10. Что такое Singleton?

Singleton — паттерн проектирования, который обеспечивает единственный экземпляр класса и предоставляет точку доступа к нему.

### 11. Как запретить копирование объекта в C++?

Копирование запрещается удалением конструктора копирования и оператора присваивания:

```cpp
ProjectManager(const ProjectManager&) = delete;
ProjectManager& operator=(const ProjectManager&) = delete;
```

### 12. В каком порядке создаются и уничтожаются объекты?

Локальные объекты обычно уничтожаются в обратном порядке создания. В составном объекте поля уничтожаются после выполнения тела деструктора, в обратном порядке объявления. Элементы контейнера `unique_ptr` освобождаются вместе с контейнером.

### 13. Может ли обычный метод изменять статическое поле?

Да. Обычный метод может обращаться к статическим полям класса и изменять их. Изменение будет видно всем экземплярам класса.

### 14. Где определяется статическое поле класса?

Для обычного статического поля определение с начальным значением размещается вне класса в одном из файлов исходного кода. Начиная с C++17 можно также использовать `inline static` внутри класса.

### 15. Когда следует использовать композицию, а когда агрегацию?

Композицию следует использовать, когда объект является частью другого объекта и его жизненным циклом управляет владелец. Агрегацию следует использовать, когда объекты могут существовать независимо, а другой объект лишь хранит ссылки на них или управляет их использованием.
